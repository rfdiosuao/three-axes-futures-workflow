## 期货工作流 5 任务（核心）

### 任务 1：全持仓期货风险扫描（交易时段每小时）

- **时间点**：`7 9-14,21-23 * * 1-5`
- **脚本**：monitor_positions.py（第一层风险监控；全持仓遍历，LEVEL=组合最高等级）
- **完整提示词（query）**：

```
本次请求是由「全持仓期货风险扫描（交易时段每小时）」定时任务到时触发的。请对期货仿真账户的【全部持仓品种】做第一层风险监控（全程只读，绝不下单、不撤单、不改单）：
1. cd 到仓库根目录（$WORKDIR，即你 clone 后的仓库路径）。
2. 运行 python3 monitor_positions.py 。脚本通过 panda CLI 读取账户、全部持仓与各持仓最新行情（凭证由 CLI 自动管理，禁止读取或展示凭证文件），用 AkShare 计算 ATR；自动遍历全部持仓，合约乘数直接用柜台 roundLot，按持仓方向判断不利涨跌停（多头看跌停、空头看涨停）。
3. 读取脚本输出第一行的 LEVEL（组合 LEVEL 取各持仓品种中的最高等级）：
   - LEVEL=WARN 或 DANGER 或 ERROR：把其后的 Markdown 简报（去掉 LEVEL= 行）用 `lark-cli im +messages-send --as user --chat-id "$LARK_CHAT_ID" --markdown "<简报>" --idempotency-key positions-scan-<年月日时分>` 发到飞书群；DANGER 在标题前加“请立即人工核对”。
   - LEVEL=NONE 或 INFO：不发任何群消息，静默结束。
4. 休市/非交易时段（周末、法定节假日，或脚本行情日不是当天、无新成交价）属正常，不是通道故障、不是登录失效：只跑脚本确认通道健康即可，不推送、不发 ERROR、不反复重试；复市后首个交易时段按真实新价恢复分级，并关注开盘跳空。
5. 仅当处在【交易时段内】且 panda/lark 登录态确实失效或脚本无法取数（须先与休市区分）时，才只发一条 ERROR 通道异常提示到该群（幂等键 positions-scan-err-<年月日时分>），不要反复重试，并在结论里说明需要重新授权。
监控规则（依据《新手操作与风控手册》）：单笔风险预算=账户权益的1%；按相对开仓价累计浮亏，达预算50%为关注(INFO)、80%为警告(WARN)、100%或逼近不利方向涨跌停（距离≤3%）为危险(DANGER)；单品种名义敞口超权益10%在简报中标注提示。Agent 只做客观风险预警，不构成买卖建议；任何平仓/离场必须用户手动确认后操作。
【频率说明】原平台最小执行间隔为 3600 秒（1 小时），故设为日盘 9:07-14:07、夜盘 21:07-23:07 每小时 07 分各一次；新平台若支持更短间隔可再加密。
```

### 任务 2：三板斧期市方向研判+信号日报（20点）

- **时间点**：`0 20 * * 1-5`
- **脚本**：daily_report.py（约 51 品种，1-4 分钟）→ sync_dashboard.py（看板同步）
- **完整提示词（query）**：

```
本次请求是由「三板斧期市方向研判日报（20点）」定时任务到时触发的。

【目标】每个交易日晚上 20:00（夜盘 21:00 开盘前），用免费数据按三板斧体系自动生成当日期市复盘飞书云文档，必须包含四部分：①开头明确的【今日方向：偏多/偏空/均衡分化】结论，并分别列出【支持看涨的证据】与【支持看跌的证据】；②【今日入场信号（扳机）】——仅在三周期共振方向，给出 20 日唐奇安通道突破（须放量≥1.2倍20日均量）与回踩日线 MA10（容差0.5%）企稳两类触发名单；③【账户持仓离场信号】——对每个实际持仓给初始止损(1.5×ATR)、吊灯跟踪止盈线(近22日极值∓3×ATR)、日线MA10 与离场状态；④在索引多维表格按日期追加一行、把当日全品种证据同步到「品种信号看板」，并把「方向+多空证据+入场扳机名单+持仓离场预警+云文档链接+索引表链接+看板链接」推送到飞书群。全程只读、绝不自动下单/平仓/撤单、不构成投资建议。

【已就绪资源，勿重新创建】
- 工作目录：仓库根目录（$WORKDIR）。
- 日报脚本：daily_report.py（python3 + akshare/pandas；扫描约51个品种，耗时1-4分钟，务必前台运行、timeout≥260s；后台任务偶发句柄丢失，优先前台重跑）。脚本已内置：确定性方向研判（meta: direction/bull_evidence[]/bear_evidence[]/long_names/short_names）；入场扳机扫描（meta: breakout_long[]、breakout_short[]、pullback_long[]、pullback_short[]，元素为品种名；规则：突破=收盘破近20日通道高/低点且当日量≥1.2倍20日均量；回踩=回踩MA10±0.5%后重新收阳/收阴并站回/压回MA10；仅对 side=long/short 的共振品种生效）；持仓离场（meta: position_exits[]，每个元素含 name/direction/qty/last/init/chan/ma10/status；init=开仓价∓1.5ATR 初始止损、chan=近22日高/低点∓3ATR 吊灯线、status 为持有中/触发吊灯/跌破初始止损/MA10转弱）；并为每个品种落盘完整证据 snapshots/evidence_<交易日>.json（含月/周/日 MA10 上下侧与方向 season/weather、20日通道、ATR、扳机 trig、价量象限 quad、止损、建议手数、反证失效条件 invalid、分层结论 conclusion 等）。XML 为九章：一盘面总览、二多空环境、三今日入场信号(扳机)、四价量四象限、五涨跌榜、六账户持仓与离场信号、七明日关注、八纪律提示、九数据口径与免责；开头有“今日方向研判”高亮块。产物：reports/daily_report_<交易日>.xml、reports/latest_meta.json、snapshots/regime_<日>.csv、snapshots/evidence_<日>.json；stdout 打印 meta JSON。
- 看板同步脚本：sync_dashboard.py（读 snapshots/evidence_<date>.json，默认最新，可用 --date 指定；把每品种证据映射到看板表字段；幂等：同日同品种已存在则更新、不存在则新增，单批≤200；末尾回读校对当日行数=证据条数）。直接 `python3 sync_dashboard.py --date <date>` 前台运行即可，无需也禁止手工拼记录。
- 飞书群、Base/表 ID：均从环境变量读取——LARK_CHAT_ID（群）、LARK_BASE_TOKEN（三板斧 Base）、LARK_INDEX_TABLE_ID（每日报告索引表）、LARK_DASHBOARD_TABLE_ID（品种信号看板表）。
- 看板表字段（28 字段）：记录/交易日/品种/代码/板块/共振方向/季节慢锚(月周)/天气快变量(日线)/状态变化/入场扳机/价量象限/MA10方向/放量确认/现价/涨跌幅%/ATR14/日线MA10/20日通道上下沿/持仓量/持仓变动/参考止损1.5ATR/建议手数/敞口封顶/每手保证金/反证·失效条件/分层结论/证据等级。建议建视图：今日总览（按交易日=Today、共振方向分组、涨跌幅排序）、多空看板（按共振方向分列）、今日扳机（Today 且入场扳机≠等待）、历史明细（按交易日降序）；并可建跨日趋势仪表盘（每日多/空/不共振家数、每日扳机数）。
- 索引表字段：报告日期(text,YYYY-MM-DD)、星期(text)、市场温度(单选，仅 偏多/偏空/均衡分化)、多头共振(number整数)、空头共振(number整数)、涨/跌(text 形如 25/25)、报告链接(text-url，写 markdown 链接)、备注(text)。
- 三板斧口径：月/周/日收盘价同在各自10均线一侧且周线日线MA10同向=多/空共振；初始止损1.5×ATR；吊灯跟踪止盈=近22日极值∓3×ATR(14)；手数=权益1%风险与单品种名义敞口10%双重约束取小；账户权益按你的实际值。方向判定：市场温度偏多且多头共振净差(多-空)≥2 才定“偏多”，偏空且净差≤-2 才定“偏空”，否则“均衡分化”。信号参数（20日/1.2倍/0.5%/1.5·3ATR/22日）为经典趋势跟踪惯例，客观可复算。证据分级：行情数值=事实(可核验)；共振/扳机=历史规则统计(相关≠因果)；看板与文档不写研究假说、新闻、概率。

【执行步骤】
1. cd 工作目录，前台运行 python3 daily_report.py，解析 stdout 的 meta JSON（date/weekday/temperature/direction/scanned/up/down/long_n/short_n/new_long/new_short/long_names/short_names/bull_evidence/bear_evidence/breakout_long/breakout_short/pullback_long/pullback_short/position_exits/top/bottom/xml_path）。若 stderr fail 品种很多或无数据，重试一次；仍失败则向群里发简短故障说明，绝不编造数据。
2. 休市/非交易日处置：若 meta 的 date 不是当天（数据日停在上一交易日，周末或法定节假日常见），或索引表中该 date 当日记录已存在，则不重复建云文档、不重复建行、不重复推日报，静默结束（必要时只在当天首次发一条极简休市说明，禁止重复刷屏）。
3. 校验XML：lark-cli docs +script --command parse --content "@./reports/daily_report_<date>.xml" --format json，要求 data.assessment.status=passed；不通过按 diagnostics 最小修复后重校。
4. 建当日云文档：lark-cli docs +create --as user --doc-format xml --content "@./reports/daily_report_<date>.xml" --format json，记录 data.document.url。
5. 索引表追加前先用 lark-cli base +record-list --as user --base-token "$LARK_BASE_TOKEN" --table-id "$LARK_INDEX_TABLE_ID" --limit 200 --format json 检查该 date 是否已存在（行数据在 data.data、列名在 data.fields）；已存在则跳过追加、不得重复建行。不存在则用 lark-cli base +record-batch-create --as user 追加一行（--json 用 @文件 传，create_records 单条）：报告日期=date、星期=weekday、市场温度=temperature、多头共振=long_n、空头共振=short_n、涨/跌="<up>/<down>"、报告链接="[三板斧期市日报·<date>](<文档url>)"、备注=新进入共振品种（如 新进入多头：豆粕、菜粕；无变化写 无共振变化）。写后 record-list 回读确认。
6. 同步品种信号看板：前台运行 `python3 sync_dashboard.py --date <date>`（timeout≥180s）。它会把 snapshots/evidence_<date>.json 的证据幂等写入看板表（$LARK_DASHBOARD_TABLE_ID，同日同品种存在则更新、否则新增），并在末尾回读打印 rows_for_date，须等于证据条数；不等则按报错定向修复一次，仍失败在汇报中如实说明，不得伪造成功。仪表盘趋势图随记录自动刷新，无需另建。休市/无新证据日跳过本步。
7. 发群（用列表、不要用 GFM 表格），lark-cli im +messages-send --as user --chat-id "$LARK_CHAT_ID" --idempotency-key "daily-report-<date>" --markdown，内容顺序：①标题【三板斧期市日报】<date>（<weekday>）；②醒目一行“今日方向：偏多/偏空/均衡分化”（直接用 meta.direction 并一句话说明含义）；③【看涨证据】2-3条（取 bull_evidence：多头共振数与名单/新进入多头、上涨家数占比、领涨板块品种、价涨仓增）；④【看跌证据】2-3条（取 bear_evidence，即使方向偏多也必须保留看跌证据，反之亦然）；⑤【今日入场扳机】分别列“突破多/突破空/回踩多/回踩空”名单（取 breakout_long/breakout_short/pullback_long/pullback_short，括号可带关键位与建议手数），四类全空则写“今日无扳机触发，共振候选继续等，不追单”；⑥【账户持仓离场预警】按 position_exits 逐行列 status（含初始止损/吊灯线/MA10），出现 🔴/🟠 必须原样提示“请人工核对、是否离场由你手动决定”，无持仓则写“当前无持仓”；⑦再用1-2行给市场温度、涨跌家数、多/空共振数、新进入多/空；⑧随后分别给『今日日报（飞书云文档）』文档URL、『历史索引（飞书表格）』你自己的 Base URL、『品种信号看板（飞书多维表格，每品种多空/扳机/止损/手数/反证可下钻）』你自己的看板 URL；⑨结尾保留“方向与信号均为客观规则结果、不是买卖指令、不预测涨跌幅、扳机不响不进场、破线必走、不构成投资建议”。
8. 宏观/地缘/财经日历具体数值免费数据无法可靠获取，脚本只给财经日历链接，禁止编造新闻、数据、概率或买卖方向；文档、看板与群消息均保留『不构成投资建议』。
9. 完成后简短汇报：当日方向、入场扳机名单、持仓离场预警、当日文档URL、索引表是否追加成功、看板同步条数（rows_for_date）、群消息 message_id；任一步失败如实说明失败点，不假装成功、不重复创建文档或记录。

【边界】Agent 只做数据筛选、信号计算与文档/表格/看板/消息搬运，绝不调用 panda 下单/平仓/撤单；入场/离场信号是客观触发名单与价位提示，不是买入/卖出推荐，是否交易、何时平仓一律由用户手动决定；文档、表格、看板、消息中不得写入手机号、凭证、open_id。账户全部持仓品种的交易时段每小时风险扫描与15:07收盘小结由其他定时任务（monitor_positions.py）负责，本任务不重复。
```

### 任务 4：长假持仓离场检查（节假日前）

- **时间点**：`35 14 * * 1-5`
- **脚本**：holiday_exit_check.py（AkShare 交易日历判断；盘中 14:35 压力测试）
- **完整提示词（query）**：

```
本次请求是由「长假持仓离场检查（节假日前）」定时任务到时触发的。

【目标】每个交易日 14:35（日盘 15:00 收盘前约 25 分钟）盘中自检一次：仅当今天是长假（春节/国庆/五一/清明/端午/中秋等，下一交易日距今≥3个自然日；普通周末仅2天不算）前最后一个交易日时，对期货仿真账户的【全部持仓】做“能否安心过节/是否应离场”的压力测试，并给出节后什么时候做多、什么时候做空的方向与入场时机，一并推送飞书群，使用户在收盘前还有时间手动减仓/平仓；普通交易日、周末、长假休市期间一律静默，不发任何消息。全程只读，绝不下单、不撤单、不改单、不自动平仓。
```
